# 消费者试摆第一轮 · 设计与实现

面向已有房间、想添置一两件家具的普通消费者。主要任务是判断搭配和摆放关系：试一件 → 调位置 → 换角度 → 添加前后比较 → 保存。首个结果是可操作的三维预览；选好摆法后再主动生成 AI 氛围效果。

## 已实现

- 首页默认「试摆一件物品」，需要一张房间照片与一张落地家具／摆件照片。自动名称，描述和尺寸折叠；「其他创建方式」保留批量、仅房间与挂画。
- 一次确认启动既有房间、物品任务。等待页显示两项实际状态，保留各自的重试／恢复入口；不使用预测百分比。两项就绪且仍停留在相应等待页、页面可见时自动进入试摆。
- 仅快捷新项目首次自动放入注册的目标物品。按中心、三角形重心、覆盖地面的固定网格寻找暂定位置，检查完整占地及可见新增物品重叠。原房间家具没有占用识别。
- 找不到位置时保存待放置状态；提供点选位置、修改尺寸、校正空间。不会自动缩小。已放置、删除或清空后不重新补回；已有保存文件优先恢复。
- 所有项目默认简易界面：贴地拖动、左右各转 15°、撤销／重做、聚焦、整个房间。拖动跨过非法位置保留最后有效位置；取消或加入第二指撤回未提交移动，一次拖动只有一个撤销步骤。双指缩放视角。
- 精细调整保留坐标轴、任意缩放、离地高度和 2D 校正；旧悬空物品保留原高度，简易移动／旋转不可用，需进入精调。
- 添加前／添加后只改变新增物品父组的显示。相机和逐件可见性保持；比较状态不序列化、不产生编辑检查点。物品编辑或生成效果图自动返回添加后。
- 保存图片支持当前视图和左右对照图。两侧用同一相机、画幅、像素尺寸，标注添加前／添加后；导出异常也恢复显示与渲染器状态。
- 保留摆放预览／AI 氛围效果切换；Flux 由用户主动运行。技术参数移入生成详情，云端提交对象与额度仍在确认处说明。

## 状态与兼容

`POST /api/projects` 可选 `experience: "quick-try-on" | "standard"`，省略为 standard；旧项目不会自动增加物品。

`POST /api/projects/:id/details` 在草稿阶段使用原有 `version` 校验，接受 `quickTryOnJobId`。任务必须属于当前项目且类别为 furniture/decor，登记后不可更换；在云端提交前登记。项目读取返回以上字段。

场景格式保留 schemaVersion 3，增加可选 `tryOn`：`jobId`、`state: pending/placed`、已放置时的 `objectId`，以及待放置恢复所需的素材与尺寸信息。移除实例不移除此记录。首次保存提交 `expectedSavedAt: null`；两个页面同时初始化时由服务端 CAS 选出一个版本，另一个读取并恢复胜出版本，不弹出用户修改冲突提示。后续用户编辑沿用原来的冲突恢复机制。

尺寸输入仍为厘米，存储为米。空输入保持默认预览比例；单轴推算其余轴；两轴保留输入，缺轴按首个已填轴推算，优先顺序为宽、深、高；三轴全部保留。`measuredAxes` 记录用户输入轴，其余为推算。旧数据没有来源时显示未核对，不重新计算尺寸。家具尺寸不改变房间尺度。

## 模块

- `try_on.mjs`：尺寸推算、来源说明、就绪判断、初始候选与初始化 CAS 协调。
- `simple_gesture.mjs`：单次拖动事务、取消回退及缩放距离计算。
- `comparison_view.mjs`：临时可见性与异常恢复、顺序对照捕获。
- `consumer_editor.mjs` / `consumer.css`：简易控制、输入接入、待放置与保存图片弹窗。
- 原编辑器继续负责对象、相机、历史与保存；后端沿用原项目、任务、素材和场景接口及访问保护。

```powershell
npm test

npm run check:repo

```
